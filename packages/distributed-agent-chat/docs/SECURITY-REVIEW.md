# Security review record

This document records a prioritized review and the state of the reviewed fixes. It is **not a security certification**, penetration test, or claim of isolation. The subprocess environment policy is filtering, not a sandbox. Findings were checked against the current implementation and focused test sources; no live provider execution is claimed.

## Findings

| ID / severity | Finding and current disposition | Fix in current source | Test evidence | Residual limit |
|---|---|---|---|---|
| SEC-01 / P1 | Child processes could inherit application/infrastructure secrets or lose credentials needed by the selected provider. | `src/agent/adapters.ts` constructs a filtered environment; provider credential allowlists are selected by mode/provider and key matching is case-insensitive. | `test/adapters.test.ts`: `child env filters application/provider secrets and retains only selected credentials`; `Claude Ollama env-check preserves only base URL and sentinel auth token`. | This is not OS-level isolation. A selected provider executable still receives the credentials intentionally passed to it; untested environment variables or provider behavior remain possible. |
| SEC-02 / P1 | Windows cancellation of only the direct child could leave descendant processes running. | On Windows, `src/agent/adapters.ts` invokes `taskkill` directly with `/T /F`, `shell: false`; non-Windows uses process-group termination. | `test/adapters.test.ts`: Windows-gated descendant cancellation fixture verifies the recorded child PID is gone. | Synthetic process-tree test only; no general sandbox or protection against all process-spawn and OS failure modes. |
| SEC-03 / P1 | Two distinct Pi issues were identified: CLI startup discarded `piConfig` output, so configured Pi tool restrictions were ineffective; managed command arguments could also be bypassed, including attached/short flags and Pi native extension/skill/template options. | `src/agent/cli.ts` now includes `piConfig` tool arguments in Pi `configuredArgs` and forwards them to the worker adapter. The CLI now includes `piConfig` tool arguments in Pi `configuredArgs` and forwards them to the adapter; `src/agent/worker.ts` validates native Pi features and requires explicit trusted opt-in; adapters construct managed arguments and default-disable Pi native features. | `test/guards.test.ts` covers guarded arguments including attached forms; `test/adapters.test.ts` checks configuration/managed arguments and default-deny behavior. Round-1 focused guard record: 6/6 passed. This is source wiring and synthetic test evidence, not live provider or tool validation. | Trust opt-in grants the requested native capabilities; tests do not establish that a provider CLI or extension is safe. |
| SEC-04 / P1 | Pi session continuity based only on provider session-ID lookup could lose or orphan sessions across restart. | `src/agent/adapters.ts` provides Pi a stable absolute session JSONL path derived from the agent identity. | `test/adapters.test.ts` covers separate invocations resuming the same session file; fixture assertions cover resumed provider IDs for Codex/OpenCode. | Synthetic fixture behavior only; no live CLI/provider compatibility or persistence durability guarantee. |
| SEC-05 / P1 | Provider completion could be accepted without validating terminal protocol state, EOF, or process exit. | `src/agent/adapters.ts` validates harness-specific terminal events and exit/session state, and bounds execution with cancellation/deadline handling. | `test/adapters.test.ts` covers terminal records, early/nonzero exit, missing terminal event, cancellation and deadline. Round-1 recorded 30 passed, 0 failed, 3 Windows EOF-specific skips. | The three Windows live-process EOF cases were skipped because Node stdio did not expose EOF in that fixture; those cases remain active on Unix. Synthetic protocol tests do not prove live provider parity. |
| SEC-06 / P2 | Equal, duplicate, or too-short chat/worker tokens could weaken credential separation. | `src/auth.ts` requires a chat token and worker tokens to be distinct and at least 24 characters; `scripts/server.ts` validates secrets before creating Miniflare. | `test/auth.test.ts` covers distinctness and minimum length; `test/server.test.ts` checks invalid startup is rejected before listening and secrets are not printed. | Length and uniqueness checks do not measure randomness or protect secrets after host compromise. |
| SEC-07 / P2 | Ordinary-object inherited properties could authenticate phantom worker IDs such as `constructor` or `__proto__`. | `src/worker.ts` uses own-property token lookup; `src/auth.ts` builds parsed mappings using own entries. | `test/auth.test.ts` covers dangerous-looking IDs as own properties; `test/room.test.ts` checks phantom claims return 401. | Authentication still depends on correct secret provisioning and transport/host security. |

## Verification scope

The cited tests are local synthetic fixtures. Historical round-1 review notes are summarized here; transient orchestration records are not part of the shipped evidence. Current source-level checks include `test/adapters.test.ts`, `test/guards.test.ts`, `test/auth.test.ts`, `test/room.test.ts`, and `test/server.test.ts`. No live provider, production environment, or hostile-host assessment is represented here. See [DEPENDENCY-AUDIT.md](DEPENDENCY-AUDIT.md) for the separate unresolved deployment blocker.
