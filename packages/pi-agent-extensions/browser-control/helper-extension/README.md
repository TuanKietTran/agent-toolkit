# Chromium MV3 helper (opt-in)

This helper talks only to the explicitly started `com.pi_agent_extensions.browser_bridge` Native Messaging host. It does not connect to localhost or any web origin. The extension does not auto-connect or select/authorize an active tab: use the toolbar popup's **Connect to native host** button, then explicitly click Allow for a listed origin. Grants are session-only; use Revoke or disconnect to remove them. The native host/broker must validate its exact extension allowlist and recheck session, target, grant, and live origin for every execution. Extension-side checks are defense in depth, not a substitute for broker authorization.

The build must package the *exact* shared `browser-control/bridge-protocol.mjs` into the MV3 runtime as `bridge-protocol.mjs`; do not hand-maintain a copy. This helper source imports `./bridge-protocol.mjs`. The host package leaf owns build integration and must place the exact shared module alongside the service worker (and at the shared package path), with no schema or validator fork. Package `manifest.json`, `service-worker.js`, `popup.html`, `popup.js`, `native-frame.mjs`, and shared protocol asset together. The published extension ID must replace/configure the native-host `allowed_origins` entry; this source intentionally does not claim a published ID.

Only canonical bounded actions handled here are observation, click, drag, text/key input, scroll, and HTTP(S) same-origin navigation. No `Runtime.evaluate`, arbitrary CDP, physical cursor movement, active-tab selection, or fallback actuator exists. Drag always attempts mouse release in `finally`. Native cancellation is best-effort: before dispatch it can prevent action; after dispatch the outcome may be uncertain and effects are not undone. Screenshot base64 uses the canonical `MAX_IMAGE_BASE64_BYTES` cap (700 KiB decoded); the shared response validator also enforces total message size beneath 1 MiB.

Chrome implements Native Messaging's 4-byte little-endian framing; `native-frame.mjs` is a pure framing codec used by unit tests, not a second live transport. Tests use the shared canonical protocol module and mock Chrome APIs; they do not prove compatibility with a running Chromium/native host. No extension installation/loading or live browser interaction was performed.
